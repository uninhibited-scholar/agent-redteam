## 一句话定位（README 顶部 hero 必须用这个）

**❌ 不要写**：
> agent-redteam 是一个开源的 LLM 红队测试工具 / 安全扫描器 / benchmark。

**✅ 要写**：
> **agent-redteam 是一个面向 LLM 安全对齐「跨通道盲区」的 Agent 探索环境。**
> 它用一套固定的样本集和评分器，让 Agent 在五个攻击通道（文本/变异/多轮/多模态/进化）上系统探索，产出可复现的对齐规律发现，而非零散的漏洞列表。

## README 结构（建议 7 段，按此顺序）

### 1. Hero（最关键）
- 一句话定位（上面的 ✅ 版本）
- 一行最 punchy 的发现作证据：`同一模型：文本防御 100/100 → 多模态防御 26.7/100（73% 跨通道塌陷）`
- 安装 + 一行复现命令（评委 30 秒内要能跑起来）

### 2. 为什么存在（Motivation）——不是"功能列表"
讲清楚要回答的**研究问题**：
> 当前 LLM 对齐是否存在随攻击通道系统性迁移的盲区？
- 引用 OWASP LLM01 / GPT-Red / arXiv:2509.05883 证明问题真实
- 强调"现有 benchmark 各自只覆盖单一通道，无人做跨通道对照"

### 3. 它是什么：探索环境（不是工具）
用**固定 / 可探索 / 反馈**三段式介绍（与问题定义文档第 3 节完全一致）：
- **固定**：14 套件、2319 样本、评分器、随机种子
- **可探索**：5 个通道维度的表格
- **反馈**：结构化反馈支持 Agent 迭代（D5 进化）

### 4. 已发现的信号（Findings）——README 的灵魂
把论文的结果表搬上来，但**每个数字配一句"它意味着什么"**：
| 发现 | 数据 | 意味着 |
|---|---|---|
| 跨通道盲区梯度 | 文本100→多模态26.7 | 对齐训练系统性偏向文本通道 |
| 结构 vs 表面 | reframe/multilingual/split 60%，case spoof 0% | 防御可能依赖表面模式匹配 |
| 稳定负结果 | 单轮文本对 GLM-5.2 = 0% bypass | 模型整体不弱，是特定通道弱 |

### 5. 快速开始（Quick Start）
- `pip install agent-redteam`
- `agent-redteam scan --target zai --model GLM-5.2 --limit 30`
- **重要**：这条命令必须真能跑通、真能出可对照日志（复赛门槛）

### 6. 复现与可检查性
- 随机种子说明
- 日志格式（评委要看 Agent 怎么行动）
- validation/ 目录的数据说明

### 7. 贡献与社区（可延续性）
- 新通道、新变异策略如何作为"可探索部分"被贡献
- 发现信号定义保持稳定（这是"环境包"可被接续的关键）

## 三个绝对不能出现的东西（会害你掉档）

1. **"又一个 benchmark"的自我定位**——会让你掉进 HarmBench/AdvBench 的红海，被有算力的团队碾压。
2. **"100% bypass rate" 当卖点**——D5 的 100% 是 n=2，统计不充分。README 里要么不提，要么老实写"Round 1 initial signal, needs larger-scale validation"。
3. **"8 model targets" 与实际只测 GLM 的不符**——如果代码里适配器没全跑通，README 不要宣传"支持 8 个模型"。改成"已适配 8 个，已完成测试的有 X 个，其余在复赛补全"。
