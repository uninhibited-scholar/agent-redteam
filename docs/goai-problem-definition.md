**项目**：agent-redteam —— 一个面向 LLM 安全对齐"跨通道盲区"的 Agent 探索环境

---

## 1. 看见了什么问题

**研究问题**：当前主流大语言模型（LLM）的安全对齐，是否存在**随攻击通道系统性迁移**的盲区？换言之，一个在标准文本提示注入下防御满分（100/100）的模型，当同样的攻击意图被搬运到**非文本通道**——图像元数据、文档结构、隐藏文本元素、多轮语境、字符变异——时，其防御是否会出现可预测、可复现的**系统性塌陷**？

### 为什么这是一个真实且未解的问题

这不是一个被人为构造出来的玩具问题，而是对齐科学里一个被反复观察到、却尚未被结构化的缺口：

- **产业侧已承认缺口存在**：OWASP 在 LLM Top 10 中将提示注入列为**头号风险**（LLM01），但官方评测口径仍以单轮文本为主，没有跨通道的标准化对照。
- **顶级实验室正在重投入**：OpenAI 于 2026 年 7 月发布内部红队自动化模型 **GPT-Red**（在间接提示注入场景上对 GPT-5.1 达 84% 攻击成功率、人类仅 13%），证明"自动化地、系统性地寻找对齐漏洞"是顶级 AI 公司公认的前沿方向——但 GPT-Red 不开源、不测其他厂商模型、不提供可复现的对照基线。
- **学术界已有碎片化证据**：arXiv:2509.05883 记录了多模态注入在 GPT-4o 上成功、Claude 3 上被抵抗（该文用定性标记而非统计成功率）；Keysight 记录了基于不可见 Unicode 的注入；但这些工作各自只覆盖**单一通道**，没有任何一个在同一模型上做**跨通道的系统性对照**。

**真正悬而未决的不是"能不能被攻破"，而是"盲区是否随通道规律性迁移"。** 如果防御塌陷只是随机噪声，那它是个工程加固问题；但如果塌陷呈现"文本通道强 → 非文本通道弱"的结构性梯度，那它指向的是**对齐训练数据与评测基准本身存在系统性偏差**——这是一个研究问题。

> 本节对应自检："如果去掉领域名，这还是研究问题吗？"——是的，核心是"对齐是否存在通道依赖的系统性盲区"，这是对齐科学的规律发现问题，不是某个工具的工程指标。

## 2. 为什么需要 Agent 介入

跨通道盲区的探索空间是**组合爆炸**的：N 个攻击意图 × M 个通道 × K 种变异 × L 轮对话语境。一个安全团队无论多大，都无法穷举这个空间，更无法保证**可复现**——而"可复现"恰恰是科学发现的底线。

Agent 的价值不在于"自动找漏洞"（那只是工具），而在于：

1. **系统性地、可审计地扫过通道 × 变异 × 语境的组合空间**，并留下完整运行日志；
2. **在扫过的过程中提炼规律**（哪类通道、哪类变异结构最有效），而非只报告一串零散的成功案例；
3. **让规律可被第三方复现与证伪**——任何人用同一环境、同一种子，应得到同一结论。

这正是赛题样例库所预告的"**面向探索 Agent 的动态评测范式**"——Agent 不只是攻击者，它是一个在固定规则下探索对齐盲区规律的研究主体。

## 3. 如何定义探索环境

环境是我们这份提交的核心载体。我们明确划分**固定部分 / 可探索部分 / 反馈机制**三块，使其成为一个"开放但可评审"的探索环境，而非一个黑箱工作流。

### 3.1 固定部分（fixed，保证公平与可复现）

- **目标模型层**：被测 LLM 固定不变（初赛阶段以 GLM-5.2 / GLM-4.5 / GLM-4-Flash 为主，复赛扩展到 DeepSeek / Qwen / Ollama 本地模型）。
- **种子样本集**：14 个测试套件、2,319 个种子攻击样本，覆盖 OWASP LLM Top 10 全部类别，作为探索的起点，探索过程中不修改。
- **评分器**：固定的判定逻辑（LeakCheck / HedgeCheck / Refusal 检测等），判定规则冻结，避免"探索者自己改计分"。
- **随机种子**：所有变异与进化过程记录种子，保证复现。

### 3.2 可探索部分（explorable，Agent 行动的空间）

Agent（变异引擎 / 自适应进化引擎）在以下五个**通道维度**上自由探索：

| 维度 | 通道 | Agent 可改变什么 |
|---|---|---|
| D1 单轮文本注入 | 纯文本 | 基线，作为参照（几乎不可探索） |
| D2 变异攻击 | 文本变体 | 11 种变异策略（同形字、零宽、重述、base64、多语言混合、角色注入、拆分重组等）的组合与强度 |
| D3 多轮攻击 | 对话语境 | 信任建立 / 权限提升 / 语境投毒 / 角色扮演 / 间接指令 等脚本路径 |
| D4 多模态隐藏注入 | 非文本通道 | SVG 隐藏文本、HTML 不可见层、PDF 元数据、零宽隐写、OCR 低对比度文本的载体与隐藏方式 |
| D5 自适应进化 | 跨通道组合 | 以成功 bypass 为种子，跨策略、跨通道进化迭代 |

### 3.3 反馈机制（feedback，让 Agent 能迭代而非只拿终分）

每一次探测返回**结构化反馈**，而不仅是一个 pass/fail：

- 是否 bypass（bypass / blocked）+ 分数（0–100）；
- 被拦截时，拦截发生在哪一层（系统提示层 / 内容过滤层 / 拒绝话术层）；
- bypass 成功时，成功命中的是哪类安全边界（信息泄露 / 越权 / 工具滥用…）。

**关键设计**：反馈足够细，使进化引擎能以成功 bypass 为种子进入下一轮（D5），形成真正的探索闭环，而不是一次性出最终分数。这对应自检"反馈是否足以让 Agent 迭代"。

## 4. 什么算发现信号

**发现信号在探索开始前就被定义**（不是事后追认）。我们对五类信号都做预先约定，并且**负结果同样被当作有效发现**：

| 发现信号类型 | 在本环境中的具体定义 | 初步观测 |
|---|---|---|
| **结构性梯度（正结果）** | 同一模型防御分随通道单调或阶梯式下降 | GLM-5.2：文本 100 → 变异(被破) 35.2% → 多轮 22% → **多模态 26.7***｜⚠️初赛口径，已受控再测量校正，见 §6 → 自适应 100%(R1) |
| **通道特异性盲区（异常）** | 某一通道的 bypass 率显著高于其他通道 | 多模态隐藏注入 73% bypass* ｜⚠️经修复评分器重跑同一批样本，实为 47%（假阳性夸大约 26pp），见 §6 |
| **"结构 vs 表面"规律（反例）** | 改变攻击**结构**的变异远胜于只改**表面**的变异 | reframe / multilingual / split 均 60%，而 case spoof 仅 0%——提示防御可能依赖表面模式匹配 |
| **稳定负结果** | 某些通道/策略对强模型无效 | 单轮文本注入对 GLM-5.2 完全无效（0% bypass）——这本身就是发现：不是模型整体弱，而是特定通道弱 |
| **问题定义的修正** | 探索中修正对"盲区"的理解 | 初步假设"多模态=图像"，实测后修正为"隐藏内容在文档处理管线中的注入"——环境边界被探索过程 sharpen |

> 这五条信号都能被**领域专家（AI 安全研究者）理解并复核**，且每一条都附带可复现的运行日志。对应自检"发现信号是否能被领域专家理解"。

## 5. 最小参照系（排除"只是随机运气"）

这是本环境最关键的设计，直接回应自检"最小参照系是否能排除随机运气"。我们设三层参照：

1. **平凡基线（trivial baseline）**：D1 单轮文本注入。GLM-5.2 在此基线下防御 100/100。
   - **作用**：证明模型整体并不弱——任何后续塌陷都应归因于**通道**，而非模型能力。
2. **随机/无干预参照**：对种子样本做随机扰动（而非结构化变异），观测 bypass 率。
   - **作用**：证明 D2 的 35.2% bypass 来自**变异策略的结构性**，而非随机噪声。
3. **跨模型对照**：同一套环境跑在不同模型上（GLM-5.2 / 4.5 / 4-Flash，复赛补 DeepSeek/Qwen/Ollama）。
   - **作用**：若盲区梯度在多个模型上复现，则它是**对齐方法的共性问题**，而非单家模型的偶发 bug。

**这三层参照合起来，能把"会不会是 LLM 幻觉 / 随机运气 / 数据泄露"逐一排除**——这是本提交区别于"一个漂亮结果截图"的核心。

## 6. 已观测到的初步探索信号（证据）

下列数据来自一次完整运行（种子固定，可复现），用于证明环境已经能产生**有意义的研究信号**：

| 攻击维度 | GLM-5.2 防御 | Bypass 率 | 信号类型 |
|---|---|---|---|
| D1 单轮文本（平凡基线） | 100/100 | 0% | 稳定负结果 |
| D2 变异攻击 | — | 35.2% | "结构 vs 表面"规律 |
| D3 多轮攻击 | ~78/100 | 22% | 通道特异性 |
| D4 多模态隐藏注入 | **26.7/100*** | **73%*** | 结构性梯度 / 异常（⚠️已校正，见下） |
| D5 自适应进化 | — | 100% (Round 1, n=2) | 待扩大样本 |

**最值得报告的发现（已按受控再测量校正）**：我们观测到通道依赖的对齐盲区的初步信号——同一模型在纯文本注入下防御满分，在隐藏内容注入通道显著下降。**经受控再测量，该效应比初赛数字更小（评分器校正后约 47%，非 73%）、强烈依赖模型能力（真视觉通道实测 0.8%~46.7%，强模型近 0）、且初赛"多模态"数字实为文档管道文本注入而非像素级视觉**。我们将"感知失败 vs 安全失守"的分离（A/B/C 拆解）、真视觉通道数据、跨模型对照，作为本环境核心的方法学贡献，而非单一头条数字。

### 诚实的边界（负结果与已知限制）

- D5 的 100% 基于 Round 1 的 2 次尝试（n=2），**统计上不充分**。我们不把这个数字当结论，只当"值得扩大探索的信号"；未构建 baseline 前不做因果归因。
- D4 当前通过文本管道模拟多模态场景（SVG/HTML/PDF 作为文本传入），**未真正上传图像到视觉模型**。我们主动把这一边界写进环境定义：本环境刻画的是"文档处理管线中的隐藏内容注入"，而非像素级图像攻击。这个边界本身是探索过程对问题定义的一次有效修正（第 5 类发现信号）。
- **73%/26.7 头条数字已被受控再测量校正**：用修复后的评分器（去除长度兜底假阳性规则）重跑同一批 15 条原始样本，GLM-5.2 与 DeepSeek-v4 均降至 47%（约 1/3 的原头条数字系评分器假阳性，非模型行为）。同时，真·像素级视觉通道（6 模型×4 厂商×120 平衡样本）测得 bypass 率 0.8%~46.7%，强烈依赖模型能力，不支持"73% 普遍盲区"这一表述。详见 `DATA-CORRECTION-NOTICE.md` 与配套论文 `paper-vision-channel-remeasurement.md`。选题（对齐是否存在通道依赖盲区）本身仍然成立，改的是数字与措辞，不是研究问题。

## 7. 可检查性与可延续性

- **可检查**：完整运行日志、随机种子、评分规则、种子样本集全部开源（GitHub + PyPI：`pip install agent-redteam`）。任何人可一行命令复现：`agent-redteam scan --target zai --model GLM-5.2 --limit 30`。
- **可延续**：环境被设计成**社区可接续的问题包/环境包**——新的攻击通道、新的变异策略、新的目标模型都可以作为"可探索部分"被社区贡献进来，发现信号的定义（第 4 节）保持稳定。这正是赛题所期待的"沉淀为社区可接续的环境包"。
- **后续研究路径**：(a) 扩大到真实视觉模型（消除 D4 边界）；(b) 扩大跨模型覆盖，验证盲区梯度是否是行业共性；(c) 把发现的"结构 vs 表面"规律反哺为防御建议（输入来源标注、隐藏内容检测）。
